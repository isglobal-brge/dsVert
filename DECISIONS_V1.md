# Decisions V1 — contract and reference

Scope: Step 1 on `feature/cross-owner-grids`, based on dsVert `9067cc7` (1.2.0) and dsVertClient `f5ed18a` (1.2.1). Promotion remains the reviewer's decision. No release route, remote method registration, package version, tag, or remote branch is changed.

1. **Add isolated internal contracts.** New specification versions are `binomial_grid_cross_v1` and `poisson_grid_cross_v1`; artifact versions are `bounded-binomial-cross-likelihood-grid-v1` and `bounded-poisson-cross-likelihood-grid-v1`. They are not added to existing dispatch. A contract is validated public metadata, not evidence that a circuit ran. State strings match the Gaussian route: `cross_owner_exact_gc_materialized` and `exact_gc_to_joint_dp_vector_v1`; `result_evidence_required=TRUE` cannot authorize release.

2. **Reuse the signed schema as the bounds authority.** Every pinned peer signs the existing schema and the new domain-separated `dsvert-cross-owner-grid-signed-contract-v1` bundle containing spec, artifact and source contract. Cross-grid validation reconstructs each derived object and checks exact canonical equality. No owner may supply a second authority for another owner's bounds. The client verifies Ed25519 and mirrors server schema normalization, including unrelated categorical schema fields.

3. **Require one existing prealigned logical dataset.** References are explicitly qualified `owner$column`, resolve through the signed dataset, and require at least two participating input owners. Exactly two computation peers are derived from policy. The outcome owner remains the anchor. Predictors and candidates must already be canonical; the validator never silently permutes a signed beta association.

4. **Keep patient-dependent alignment material private.** The public alignment digest covers only logical snapshot metadata, alignment group and protocol. `public_patient_dependent_hash=FALSE` is mandatory. The source contract requires existing recipient-specific XOR alignment sharing. It does not publish an ordered patient-manifest digest or complete-case count. Runtime source claims and the actual private alignment gate are later integration work.

5. **Freeze a source-only Ring128 layout.** Source version is `dsvert-biomedical-capsule-source-contract-v6-cross-grid-xor-alignment`, with purpose `biomedical_capsule_ring128_cross_grid_inputs_and_release_shares_only`. The release prefix contains one zero coordinate per candidate, then zero padding to the next 8192-coordinate boundary, matching Gaussian source chunking. In predictor order and then outcome order, each input has N values followed by N binary validity records. Features use normalized unsigned f50 encoding; outcome and validity use integer f0 encoding. Missing/padded records contain zero values and zero validity. All records are 16-byte Ring128 shares. The signed complete-case rule ANDs every input validity with private alignment for every candidate.

6. **Preserve the existing preprocessing interpretation explicitly.** Each finite raw record is clipped, patient values are averaged, predictors are normalized, and a bounded outcome mean must be binary or an integer count. Out-of-range raw records may become valid after clipping, as in the existing materializer. The numeric proof starts at the normalized-value encoding boundary; future source code must not add unbudgeted encoding error or independently round owner partial predictors.

7. **Separate internal precision from output precision.** Use f=50 for features and public beta, q=64 for nonlinear evaluation, and signed 192-bit arithmetic. Public coefficients and nonlinear constants use signed decimal integer strings. Beta at magnitude 8 encodes as 2^53, which is exactly representable in binary64 but outside the transport’s allowed integer domain of at most 2^53-1. Transported features are at most 2^50; released caps, maxima and sensitivities must remain at most 2^53-1. Output g remains 8–18, p is 1–16, candidate count is 1–256, |beta_k|<=8, sum|beta_k|<=16, and Poisson M is 1–1024. Intercept-only grids are outside this version, consistent with the existing nonempty-predictor grid contract.

8. **Certify accuracy before optimizing kernel cost.** Pin the full profile `cross-grid-chebyshev-q64-softplus256-exp32-v1`: degree-256 softplus and degree-32 quarter-exp on the shared Chebyshev argument eta/17, followed by two q64 squares. A public q64 log-factorial table covers 0–1024. All coefficient/table integers, evaluation order, precision, bounds and error claims are hash-bound. Coefficients are certified with outward interval arithmetic; analytic Bernstein-ellipse tails and exact rational error inequalities establish uniform bounds. Sampling is a regression check only. The conservative degree/width may be expensive; Step 2 must measure actual gates, memory and runtime before promotion.

9. **Round once after the complete dot product.** Include the intercept once at f100, accumulate every public-beta product exactly, then round to q64. Clenshaw evaluation, division by 17, exponential squarings and output quantization all use nearest, ties to even, including negative ties. Binary outcomes use a mux; Poisson uses integer multiplication and private log-factorial selection. Mask invalid rows, clamp loss to `[0,U_j/S]`, round to an integer at scale S, then sum. No result depends on how predictors are partitioned between owners.

10. **Use the inherited sensitivity formulas with an explicit integer clamp.** U_j=ceil(S L_j), Delta_1=a sum U_j, Delta_2=a sqrt(sum U_j^2), and coordinate maximum=N U_j. Both add/remove and `replace_one_fixed_cohort` are supported with multipliers 1 and 2. L2 retains the server's existing outward floating-point guard. Server tests call the actual same-owner builder; client tests call the existing loss-bound helper. The public binary64 cap formula is not newly interval-certified. For example, `exp(log(12))` in binary64 can equal 12 although exp of that exact binary64 log value is slightly larger. Sensitivity remains exact because of the clamp. The uniform error statement is against the equally clamped real loss; extending it to the unclamped real loss requires cap enclosure.

11. **Canonicalize and validate public numeric edge cases.** Normalize encoded negative zero to `"0"`. Check raw beta L1 with an error-free floating expansion, so a rounded R sum cannot admit a true binary64 sum above 16. The integer oracle checks the upward-rounded integer bound ceil((p+1)/2) on the summed half-ulp coefficient-encoding budget. The signed raw coefficient domain and certificate still enforce the actual per-coefficient half-ulp error. Scalar fields remain scalars across R/JSON/Go; arrays are only accepted where the schema declares them.

12. **Keep references test-only and independent.** Go uses `math/big` integer arithmetic and an independent 256-bit transcendental oracle. Pure R helpers use signed base-2^15 limbs; no native big-number package or inexact large product is used. R, Go and the generator share public synthetic batch fixtures, including deliberately small saturation caps. These helpers do not access protected data and are not constant-time production implementations.

13. **Freeze a public batch traversal, not an unmeasured resource claim.** Artifact transcript uses row batches of min(32,N), candidate batches of min(8,m), row-batch-then-candidate-batch traversal, and two-authority additive candidate-sum-share outputs only. The private source layout is limited to 64*1024^2 coordinates. A future engine must validate resource feasibility before protected input resolution. This step does not claim the batch is cheap or that a GC operation already exists.

14. **Preserve a pristine comparison for long suites.** Go baselines execute from a tracked-file archive of the exact starting server commit. R baselines use paired pristine local checkouts with the expected `dsVert` / `dsVertClient` basenames so companion discovery and source-only tests exercise the intended pins. After tests use the working feature branches. Initial exploratory runs were stopped when their timing made the default package-wide Go timeout unsuitable; authoritative complete Go runs disable that timeout while retaining every test and all per-test deadlines. Full before/after counts and any baseline failures are recorded in `STATUS_V1.md`; interrupted or incorrectly paired exploratory runs are not counted as authoritative completed suites.

15. **Use fixed transcript-safe failure boundaries.** Server entry validators route errors through `.dsvert_dp_transcript_stop`. Client failures use the same fixed public failure code/message and discard lower-level condition details. No rejected bound, identity, intermediate loss or protected value is interpolated into an error response.
